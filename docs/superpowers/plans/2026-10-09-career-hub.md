# Career Hub and Navigation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an admin-managed career-learning article library with public search/filter/detail pages, and condense landing-page navigation into accessible React + Motion dropdowns.

**Architecture:** Store article metadata and text content in PostgreSQL using Drizzle. Add admin-protected CRUD/publish APIs and public published-only read APIs, then build the public index/detail and admin editor on existing app patterns. Keep dropdown components small and local to the landing page; reuse existing mobile menu state and i18n.

**Tech Stack:** Next.js 15 App Router, React 19, TypeScript, Drizzle ORM/PostgreSQL, Zod 4, Motion (`motion/react`), Tailwind CSS 3, Vitest.

## Global Constraints

- Keep DOCX/PDF import and downloadable attachments out of this phase; remember them as a future phase.
- No new dependency for editor or search.
- Keep existing teal tokens, Material Symbols, admin authorization, and localization patterns.
- Never expose drafts through public APIs, search, metadata, or pages.
- Treat article content as text/structured paragraphs; do not render arbitrary HTML.
- No fabricated sample articles, testimonials, statistics, identities, or claims.
- Every data UI has loading, empty, and error states.
- Dropdowns work with pointer and keyboard, close on Escape/outside click/navigation, and honor reduced motion.
- Preserve unrelated pre-existing working-tree changes; inspect and reconcile partial nav edits before touching them.
- Use standard text without em dashes in user-facing UI copy.

## Task 3: Build public/admin Career Hub API

**Files:**
- Create: `src/app/api/career-hub/route.ts`
- Create: `src/app/api/career-hub/[slug]/route.ts`
- Create: `src/app/api/admin/career-hub/route.ts`

- Create as needed: `src/lib/career-hub-data.ts`
- Create: `src/__tests__/career-hub-api.test.ts`

**Interfaces:**
- Public `GET /api/career-hub?q=&category=&tag=&page=&pageSize=` returns `{ posts, pagination, filters }`, published only, newest first.
- Public `GET /api/career-hub/[slug]` returns a published post or 404.
- Admin `GET /api/admin/career-hub?status=&q=` returns drafts and published records.
- Admin `POST /api/admin/career-hub` creates draft by default; published creation only when explicitly requested.
- Admin `PATCH /api/admin/career-hub/[id]` edits fields and performs publish/unpublish transitions; first publish sets `publishedAt`, edits preserve it, unpublish clears it, republish sets a new timestamp per spec.
- Admin `DELETE /api/admin/career-hub/[id]` deletes after UI confirmation.

- [ ] Add tests first for public draft exclusion, draft slug 404, category/tag/search composition, pagination limits, unauthenticated admin rejection, non-admin rejection, duplicate slug, create draft, update, publish, unpublish, and delete.
- [ ] Run focused test file and confirm expected failures.
- [ ] Implement public parameterized Drizzle filters, stable ordering, bounded pagination, and select only fields required by public pages.
- [ ] Implement admin routes with `withAdmin`, `apiHandler`, `errorResponse`, schemas, unique slug handling, and consistent JSON response shapes.
- [ ] Handle slug uniqueness races by catching database unique constraint and returning `DUPLICATE_SLUG`.
- [ ] Verify public endpoints cannot return draft fields even if caller guesses slug or passes status parameters.
- [ ] Run focused API tests.
